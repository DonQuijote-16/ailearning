# Design: Issue #2 — AI 学习大纲（入口文档）

## 背景

仓库用于个人记录与推进 AI 学习，当前内容极少。需要在仓库内建立第一份可持续维护的总览文档，作为项目入口，明确学习顺序、各阶段能力与自检产出，并为后续周计划、笔记与练习预留约定路径。

## 目标

- 新增一份主大纲 Markdown，结构完整（阶段划分、每阶段简述、自检/产出建议），中文为主、表述通顺。
- 可选：`docs/` 固定文档位置；根目录 `README.md` 一句话定位并链接到大纲。
- 撰写本设计文档，说明文档结构、路径选择与后续扩展方式。

## 非目标

- 不与尚不存在的 `plan.txt` 对齐；不预先创建 `week1/` 等目录或空目录占位（大纲内仅以「计划用于…」约定路径）。
- 不要求 Web、数据库或重型依赖。

## 方案概述

- **主大纲路径**：`docs/ai-learning-outline.md`。与自动化设计文档同置于 `docs/`，便于后续在 `docs/` 下扩展笔记索引等，且不污染根目录列表。
- **入口**：更新根目录 `README.md`：项目名称/一句定位 + 相对链接至 `docs/ai-learning-outline.md`。
- **大纲内容**：学习目标（个人向 bullet）→ 分阶段路线图（阶段名、核心主题、侧重技能）→ 每阶段可勾选自检/产出 → 仓库使用约定（`plan/`、`week-n/` 等为**计划**用途表述，不写已存在文件）。

## 数据 / API / UI 触点

无。纯文档变更。

## 文件级变更计划

| 文件 | 动作 |
|------|------|
| `docs/automation/issue-2-ai-learning-outline.md` | 新增（本设计文档） |
| `docs/ai-learning-outline.md` | 新增（AI 学习总览大纲） |
| `README.md` | 修改（定位 + 链接） |

## 测试计划

仓库无自动化测试或 Markdown 校验脚本。验证方式：本地通读大纲与设计文档，确认无指向「已存在」的不存在路径，相对链接有效。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 与后续实际目录名不一致 | 大纲与 README 仅约定建议路径，后续可在 PR 中微调并同步大纲「仓库约定」一节。 |

## 上线 / 维护说明

合并后维护者可在 `docs/ai-learning-outline.md` 中增删阶段或自检项；周计划与练习目录按约定创建后再在大纲中增加「已存在」链接。
